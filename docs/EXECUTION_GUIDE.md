# Execution Guide

This guide covers two execution modes: running tests locally against a live site, and running tests automatically via GitHub Actions CI/CD.

---

## Mode Overview

| | Local Execution | CI/CD Execution |
|---|---|---|
| Target site | Your live remote site | Fresh Docker WordPress on localhost:8080 |
| Credentials | `.env` file | GitHub Secrets + workflow env block |
| Trigger | Your terminal | Push to `main`/`qa`, or manual dispatch |
| Browser | Headed or headless | Headless only |
| WooCommerce keys | Manually generated | Auto-generated by `setup-ci-environment.ts` |

---

## Part 1: Local Execution (Against a Live Site)

### 1.1 Prerequisites

**Step 1**
Action: Install Node.js 18 or later from [nodejs.org](https://nodejs.org/).
Expected result: Running `node -v` prints `v18.x.x` or higher.

**Step 2**
Action: Install Git 2 or later from [git-scm.com](https://git-scm.com/downloads).
Expected result: Running `git --version` works in terminal.

**Step 3**
Action: For Google Sheets tests, prepare a Google service account JSON from [Google Cloud Console](https://console.cloud.google.com/). The service account must have Editor access to your target Google Sheet.
Expected result: You have the JSON file ready to place in the project.

---

### 1.2 First-Time Setup

**Step 1**
Action: Clone the repository and open the project folder in terminal.
```bash
git clone https://github.com/wppool/flexorder-e2e-automation.git
cd flexorder-ci-workflow
```
Expected result: You are inside the project directory.

**Step 2**
Action: Install project dependencies.
```bash
npm ci
```
Expected result: All packages install successfully with no errors.

**Step 3**
Action: Install the Playwright browser.
```bash
npx playwright install --with-deps chromium
```
Expected result: Playwright downloads Chromium and its system dependencies without error.

**Step 4**
Action: Copy `.env.example` to `.env` and fill in your values.
```bash
cp .env.example .env
```
Then open `.env` and set each variable:

| Variable | Description | Where to get it |
|---|---|---|
| `SITE_URL` | Root URL of your live test site | Your hosting panel |
| `ADMIN_PANEL_URL` | WordPress admin login URL | `SITE_URL` + `/wp-admin/` |
| `USER_NAME` | WordPress admin username | Your site credentials |
| `PASSWORD` | WordPress admin password | Your site credentials |
| `WOOCOMMERCE_CONSUMER_KEY` | WooCommerce REST API consumer key | WooCommerce → Settings → Advanced → REST API → Add Key (Read/Write) |
| `WOOCOMMERCE_CONSUMER_SECRET` | WooCommerce REST API consumer secret | Same as above |
| `FLEXORDER_PRO_LICENSE_KEY` | FlexOrder Pro license key | Your license account |
| `GOOGLE_SHEET_URL` | Full URL of the Google Sheet used by tests | Your Google Drive |
| `SHEET_NAME` | Tab name inside that sheet (e.g. `Orders`) | Your Google Sheet |
| `SERVICE_ACCOUNT_UPLOAD_FILE` | Path to the service account JSON file | Leave as `./tests/fixtures/upload_key.json` |

> **Important:** Do not add `CI=true` to your `.env`. That flag is injected automatically by GitHub Actions and forces the CI execution path, which will break local runs.

Expected result: Your `.env` file is saved with all required values filled in.

**Step 5**
Action: If running Google Sheets tests, place your service account JSON file at `tests/fixtures/upload_key.json`.
Expected result: Running `npm test` does not warn about a missing service account file.

### 1.3 Running Tests Locally

**Run all tests (headless, default):**
```bash
npm test
```

**Run all tests with a visible browser:**
```bash
NON_HEADLESS=true npm test
```

**Run a single spec file:**
```bash
npx playwright test tests/specs/a-flexorder-setup.spec.ts
```

**Run a single spec file with visible browser:**
```bash
npx playwright test tests/specs/a-flexorder-setup.spec.ts --headed
```

**Run with interactive UI mode (step through tests visually):**
```bash
npm run test:ui
```

**Run in debug mode (pauses on each action):**
```bash
npm run test:debug
```

**Open the HTML report after a run:**
```bash
npm run test:report
```

**Slow down test actions for visual debugging** (value in seconds):
```bash
SLOWMO=0.5 npm test
```

---

### 1.4 Test Execution Order

Tests run sequentially in this order (alphabetical spec names, prefix `a-` runs first):

1. `a-flexorder-setup.spec.ts` — Login and FlexOrder wizard setup
2. `a-activateProVersion.spec.ts` — Pro license activation (requires `FLEXORDER_PRO_LICENSE_KEY`)
3. `a-woocommerceAPI.spec.ts` — WooCommerce REST API connectivity
4. `createNewOrder.spec.ts` — Order creation (currently commented out)
5. `ultimateSettings.spec.ts` — Ultimate settings and Google Sheets validation
6. `update-order-status.spec.ts` — Google Sheets to WooCommerce status sync

> Tests 5 and 6 require `GOOGLE_SHEET_URL`, `SHEET_NAME`, and a valid `upload_key.json`.

## Part 2: CI/CD Execution (GitHub Actions)

### 2.1 How CI/CD Works

When a run starts, the workflow automatically:
1. Starts a fresh Docker WordPress environment on `localhost:8080`
2. Installs WordPress core, WooCommerce, FlexOrder Free, and FlexOrder Pro
3. Creates test products and orders
4. Generates WooCommerce API keys via `setup-ci-environment.ts`
5. Runs the full Playwright test suite headlessly
6. Uploads test reports and artifacts
7. Sends Slack/email notifications (if secrets are configured)
8. Tears down all Docker resources

No manual environment setup is needed — the workflow builds everything from scratch.

---

### 2.2 Required GitHub Secrets

Before CI/CD can run successfully, configure these in:
**Repository → Settings → Secrets and variables → Actions → New repository secret**

| Secret Name | Description | Required |
|---|---|---|
| `APP_ID` | GitHub App ID for accessing private plugin repos | Yes |
| `APP_PRIVATE_KEY` | GitHub App private key | Yes |
| `FLEXORDER_PRO_LICENSE_KEY` | FlexOrder Pro license key | Yes |
| `GOOGLE_SHEET_URL` | Google Sheet URL for order sync tests | Yes (for Sheets tests) |
| `SHEET_NAME` | Sheet tab name (e.g. `Orders`) | Yes (for Sheets tests) |
| `GOOGLE_ACCOUNT_EMAIL` | Google account email used in browser tests | If needed |
| `GOOGLE_ACCOUNT_PASSWORD` | Google account password | If needed |
| `SLACK_WEBHOOK_URL` | Slack incoming webhook for notifications | Optional |
| `SMTP_SERVER` | SMTP server address for email reports | Optional |
| `SMTP_USERNAME` | SMTP login username | Optional |
| `SMTP_PASSWORD` | SMTP login password | Optional |
| `EMAIL_TO` | Recipient email address for test reports | Optional |

---

### 2.3 Triggering a CI/CD Run

**Automatic triggers:**
- Push a commit to the `main` or `qa` branch
- A push to `WPPOOL/flexorder` or `WPPOOL/flexorder-ultimate` sends a `repository_dispatch` event that starts the workflow automatically

**Manual trigger:**

Step 1: Open the repository on GitHub and click **Actions**.
Expected result: You can see the workflow named `FlexOrder CI/CD Pipeline`.

Step 2: Click the workflow name, then click **Run workflow** on the right side.
Expected result: A branch selection dropdown appears.

Step 3: Select the branch you want to test against (`main` or `qa`).
Expected result: The workflow is ready to start.

Step 4: Click the green **Run workflow** button.
Expected result: A new workflow run appears in the list within a few seconds.

---

### 2.4 Monitoring a CI/CD Run

Step 1: Click the running workflow entry to open the job detail.
Expected result: You can see each step executing in real time.

Step 2: Watch the steps in order: Checkout → Node setup → Docker start → WordPress install → Plugin deploy → Test provisioning → E2E tests → Cleanup.
Expected result: Each step shows a green check when complete.

Step 3: After the run finishes, scroll to the **Artifacts** section at the bottom of the run summary.
Expected result: You can see downloadable artifacts: `test-results`, failure screenshots, and failure videos.

Step 4: Download `test-results` and open `playwright-report/index.html` in your browser for the full HTML report.
Expected result: You see a detailed breakdown of every test — passed, failed, and skipped.

> **Note:** This workflow runs on a self-hosted Windows runner. If the runner shows as `Offline` in `Settings → Actions → Runners`, the run will stay queued until the runner is restarted. Contact the internal QA or DevOps owner.

## Part 3: Troubleshooting

### Local Issues

**Problem: "Executable doesn't exist" or browser launch error**
Action: Playwright browsers are not installed. Run:
```bash
npx playwright install --with-deps chromium
```
Expected result: Browser installs and tests run on the next attempt.

**Problem: "No tests found" error**
Action: The command syntax is wrong. Use the correct format:
```bash
npm test
# or for a specific project:
npx playwright test --project=flexorder-e2e
```
Do not use `-- project` (with a double dash and space) — that passes `project` as a file name pattern.
Expected result: Tests are discovered and run correctly.

**Problem: "Missing required environment variables: SITE_URL"**
Action: Your `.env` file is missing `SITE_URL` or is not being loaded. Verify:
1. The file is named `.env` (not `.env.example` or `.env.txt`)
2. `SITE_URL=` is present and has a value
3. You have not set `CI=true` in `.env`

Expected result: Global setup passes validation and tests proceed.

**Problem: "WooCommerce credentials not found"**
Action: Add `WOOCOMMERCE_CONSUMER_KEY` and `WOOCOMMERCE_CONSUMER_SECRET` to your `.env`. Generate keys from: WooCommerce → Settings → Advanced → REST API → Add Key (Read/Write permissions).
Expected result: API-dependent tests connect to WooCommerce successfully.

**Problem: Google Sheets tests fail or are skipped**
Action: Check three things:
1. `GOOGLE_SHEET_URL` and `SHEET_NAME` are set in `.env`
2. `tests/fixtures/upload_key.json` exists and contains valid service account JSON
3. The service account has Editor access to the target sheet

Expected result: Sheets tests execute and read/write data successfully.

---

### CI/CD Issues

**Problem: Workflow stays queued and never starts**
Action: Go to `Settings → Actions → Runners` and check the self-hosted runner status.
- `Idle` = runner is online and ready
- `Offline` = runner is not running — contact the internal QA or DevOps owner

Expected result: You understand why the run is waiting and who can resolve it.

**Problem: "Generate GitHub App Token" step fails**
Action: Verify that `APP_ID` and `APP_PRIVATE_KEY` are set in repository Secrets. These are required to download private plugin zips from `WPPOOL/flexorder` and `WPPOOL/flexorder-ultimate`.
Expected result: Token generation succeeds and plugin downloads proceed.

**Problem: Pro license activation test fails in CI**
Action: Ensure `FLEXORDER_PRO_LICENSE_KEY` is set in repository Secrets.
Expected result: The license is passed to the test and activation completes.

**Problem: WordPress or MySQL container never becomes healthy**
Action: Open the workflow run log, find the "Wait for Services" step, and check Docker logs printed on failure. The containers have memory limits (1GB WordPress, 512MB MySQL) — insufficient runner memory can prevent startup.
Expected result: Containers become healthy and setup proceeds.

## Part 4: Reading Test Results

**From local runs:**
1. Results print to the terminal during the run
2. Run `npm run test:report` to open the HTML report in your browser
3. Screenshots and videos for failed tests are saved in `test-results/`

**From CI/CD runs:**
1. Open the workflow run on GitHub → look for the green check or red X
2. Click the job to read step-by-step logs
3. Download the `test-results` artifact from the Artifacts section at the bottom of the run summary
4. Open `playwright-report/index.html` from the downloaded folder in your browser
5. If Slack notifications are configured, a summary message is posted automatically after each run

**Result icons:**
- Green check (✅) = all tests passed
- Red X (❌) = one or more tests failed — check logs, screenshots, and the HTML report
- Orange dot (⏸) = run is queued, waiting for a runner
